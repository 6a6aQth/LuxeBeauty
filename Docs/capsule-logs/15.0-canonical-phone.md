## Key Changes

One stored phone: `+` and digits only. Malawi local forms, including brackets, an extra `0` after `+265`, a leading `O`, Unicode spaces, and bidi marks, collapse to `+265` plus 9 digits. A number that already starts with `+` and another country code is stored as digits-only E.164. Names, junk, and country-less numbers such as `07740971277` are rejected on input and left unchanged by the rewrite.

Checkout, signup, and admin edit save that value. Loyalty preview, payment verification, and the webhook count successful bookings that canonicalize to the same number. Verification and SMS use the phone on the booking. Account visits and account reschedule compare canonical phones.

The rewrite ran with `--apply` on 2026-09-25. 1,804 bookings rewritten, 67 left unchanged, 1 profile rewritten (`0885535374` → `+265885535374`). No profile collision.

## Architecture Decisions

- `lib/phone.ts` has no database access so the booking form, signup, and admin page can import it.
- Equivalent rows are matched in application code, because spacing variants cannot be listed in a Prisma `in` filter.
- A 9-digit string that starts with `0` is not treated as a Malawi number. It is one digit short of `0` plus 9 digits.
- A `+265` value that is not 9 subscriber digits, or `+265` plus an extra `0` and 9 digits, is rejected rather than stored as a short international number.
- Unicode spaces and bidi marks are stripped so a pasted Malawi number can canonicalize.
- The booking, signup, and admin phone boxes do not show the long Malawi/international hint. A bad number stays on the page and the toast says "That phone number format is not okay."
