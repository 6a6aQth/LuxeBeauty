## Key Changes & Architecture Decisions
- **Prisma Schema & Database:** Added `blocked Boolean @default(false)` to `CustomerProfile`. Database updated and verified against Neon PostgreSQL.
- **Admin Moderation API:** Created admin-only `POST /block`, `POST /unblock`, and `DELETE` endpoints for users by ID. Delete operates cleanly on `CustomerProfile` without deleting booking records, ensuring audit trails and financial receipts remain intact.
- **Live Admin UI:** Added responsive three-dot action menu to each user row in `UsersPanel` offering Block/Unblock toggle, Delete modal with explicit impact warning, and status badges.
- **Sign-in & Mid-Session Guard:** When an authenticated user has `blocked === true`, sessions are terminated via `signOut()` and routed to `/blocked`. Mid-session actions on `/account`, `/api/account/visits`, `/api/account/profile`, and reschedule verify the flag and force signout.
- **Guest Booking Guard:** Prior to initializing a Direct Charge in `app/api/paychangu-checkout`, the submitted phone is canonicalized to E.164 and queried against `CustomerProfile`. If blocked, charge initialization is halted with 403 and the user-facing block notice is returned.
