## Key Changes & Architecture Decisions
- **Single API call:** `GET /api/account/visits` now returns `totalDurationMinutes` and `expenditure` together, so the account page does not need a separate catalog fetch (24.3 satisfied).
- **Duration computation is live-catalog:** Resolved against current `Service.duration`; deleted-service ids silently contribute 0 (FR-32 spec). Same logic for expenditure (using `price` at read time, consistent with existing Expenditure spec from FR-28 / Capsule 20).
- **Booking form duration bar:** Placed inside the existing sticky total bar as a second `flex` row. Uses `text-xs text-stone-600` to remain visually secondary to the MWK total. Fully responsive with `break-words` on the same grid that already satisfies FR-27 narrow-screen constraints (24.4 satisfied).
- **Conditional render:** Both account-page widgets are hidden when value is 0 — a fresh account with no past visits shows neither, keeping the sidebar clean.
