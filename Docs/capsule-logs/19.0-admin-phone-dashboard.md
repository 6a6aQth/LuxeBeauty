## Key Changes

After the existing password, `/admin` opens on Overview. A black nav lists Overview, Bookings, Availability, Services, Users, Newsletter, and Price list. A wide screen keeps that nav on the left. A narrow screen opens the same nav from a menu button.

The line counts bookings with status `successful`. Week and month height is that day’s count divided by `getSlotsForDate` for that weekday. A day with no slots, including Sunday, sits at zero. Year height is the month’s count divided by every offered slot in that month. Each point shows the count. Previous and next move one period.

Users lists each `CustomerProfile` name, email, and phone. The three-dot menu says nothing can be changed from there and calls no API.

Bookings, availability, services and categories, the newsletter form, and the price-list upload keep their current actions. Categories stay inside Services.

## Architecture Decisions

- Fullness is calculated in `lib/admin-overview.ts` from calendar dates at noon UTC, so Africa/Blantyre weekdays match `getSlotsForDate`.
- Overview loads `/api/bookings?status=successful` on its own, so the booking status filter does not empty the line.
- The users route returns only name, email, and phone. It is not session-protected, same as the other admin reads today.
- The sidebar photo is `/images/nails-1.jpeg`. The wordmark is set in the page, with Great Vibes for “luxe”, because `Llogo.png` has a gray background that would show as a box on black.
