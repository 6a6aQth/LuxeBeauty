## Understanding Summary

**Purpose:** Add `"08:00"` as a conditional overflow slot for Mon–Fri (not Saturday). It only appears in the slot picker when every regular slot on that date has ≥ 1 successful booking. It carries a distinctive "Early Access" badge. The server re-validates the overflow condition before creating a booking at 08:00. No additional payment logic — FR-01's existing charge = stored service total already enforces full payment.

**Code Areas:**
- `lib/time-slots.ts` — add `OVERFLOW_SLOT` constant; keep it out of `getSlotsForDate`
- `lib/payments.ts` — new `isOverflowSlotAvailable(dateStr)` function, overflow re-validation in `startPayment`, code comments documenting full payment guarantee
- `app/api/unavailable-dates/route.ts` — extend GET with `date` parameter support returning overflow availability
- `app/api/slots/route.ts` — add dedicated slot query endpoint (`GET /api/slots?date=YYYY-MM-DD`)
- `components/booking-form.tsx` — render "Early Access" badge on the 08:00 slot option
- `app/booking/page.tsx` — dynamically inject `08:00` into available slots only when all regular slots are booked; adjust `fullyBookedDates` so dates with 08:00 available remain selectable

**Expected Outputs:**
- `"08:00"` absent from picker unless all regular slots are fully booked
- When present: "Early Access" badge displayed, slot is selectable and functional
- Server rejects 08:00 bookings if condition no longer holds (race guard)
- Code comment in checkout route documents that FR-01 already satisfies the full-payment requirement
